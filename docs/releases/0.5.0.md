Added

- The plugin now activates and runs on sites whose database tables use MyISAM. Before, activation failed unless every table used InnoDB.

Changed

- Activation fails only when a table uses an engine other than InnoDB or MyISAM, and the message names both engines.
- The plugin still creates its own tables as InnoDB. It does not convert existing tables.
- MyISAM has no rollback. If the database fails partway through an operation on a MyISAM table, the changes already saved stay. InnoDB is the safer choice. The README explains how to convert a table.
- On a MyISAM usermeta table, a setup link is used up when saving the passkey fails. Send the owner a new link.

Upgrade from v0.4.1

- The upgrade changes no data. Passkeys, settings and logs stay as they are.
- Sites whose tables use InnoDB work as before.

Upgrade from v0.3.0

- This upgrade includes the v0.4.0 and v0.4.1 changes. The upgrade keeps existing passkeys, account handles, settings, and password restrictions. Users do not need to register their passkeys again.
- The upgrade permanently deletes the old diagnostic log table and its history. Export or back up that history before upgrading if you need to keep it.
- The schema update runs on the next request. If it fails, it retries after five minutes.
- The plugin installs its watchdog in wp-content/mu-plugins. If that directory is not writable, an administrator notice reports that deactivation protection is off, and the plugin retries the install after an hour.

Changed

- Passkey lists and Passkey Logs use the standard WordPress table layout. Rename and Remove appear as row actions, and Rename opens a Quick Edit row instead of a browser prompt.
- Added and last-used times from the past seven days show as relative time, such as "3 days ago". Hovering a time shows the exact date and time.
- After a successful passkey test, the list highlights the passkey that answered.
- Your own empty passkey list explains how to add a passkey. Another account's empty list says that account has no passkeys yet.

Fixed

- On a profile, you can't turn on Passkey only mode until the account has a passkey that works on this site.
- In settings, the Enable and Disable options stack like core WordPress settings. You can't enable Passkey only mode while passkeys are unavailable.
- In the frontend passkey list, column headings no longer break mid-word, Rename and Remove stay on one line, and the Quick Edit row no longer picks up the theme's fieldset border and padding.

Upgrade from v0.4.0

- The upgrade changes no data. Passkeys, settings and logs stay as they are.

Upgrade from v0.3.0

- This upgrade includes the v0.4.0 changes. The upgrade keeps existing passkeys, account handles, settings, and password restrictions. Users do not need to register their passkeys again.
- The upgrade permanently deletes the old diagnostic log table and its history. Export or back up that history before upgrading if you need to keep it.
- The schema update runs on the next request. If it fails, it retries after five minutes.
- The plugin installs its watchdog in wp-content/mu-plugins. If that directory is not writable, an administrator notice reports that deactivation protection is off, and the plugin retries the install after an hour.

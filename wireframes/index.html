Low-fidelity, clickable wireframes of every interface the plugin currently ships. Pick a screen on the left, then use the state chips above each frame to see the variants. Copy matches the plugin's strings. Nothing here talks to a server.

Core journeys

Open login→Sign in with a passkey→Browser prompt (biometric / PIN)→Verifying→Redirect

Profile→Add passkey→Browser prompt→Saved as “Chrome on Mac”, list refreshes, owner emailed

Admin: Send passkey setup link→Owner opens the email link→Add passkey→Sign-in page: "Passkey added. Sign in with it now."

Register (optional mode)→Signed in at once→Profile, Add passkey focused→Add passkey

Sign-in is always usernameless. The browser picks the account, so there is no username field on the passkey form.

Login page

wp-login.php with a passkey button added to the native login form. Passkey only mode is an on/off switch: off shows the password form and the passkey button, on shows only the passkey button.
